# 常见问题 FAQ（含迁移指引）

> 覆盖评测与用户反馈中的高频问题。没找到答案时，先跑 `python scripts/pipeline.py 你的文件 -o out.txt` 看报告，再按报告里的指南深改。

## 基础

**Q0：第一次用，最容易踩的坑？**
读 `references/pitfalls.md`——20 条集中式常见错误清单（参数误用/编码事故/守卫
误读/流程合规），每条带正确做法。TL;DR：跑 pipeline → 读报告 → 按指南深改 →
verify → compare。

**Q1：这个工具和 paper-polisher-pro 什么区别？**
paper-polisher-pro 是综合润色工具箱（术语、翻译腔、比喻审计、AIGC 标识合规、期刊预检），本工具专攻「风格自然化」一件事：风格特征自查 → 机械清理 → 深改简报 → 完整性守卫。两者可同时使用互不冲突——先本工具去模板腔，再 paper-polisher-pro 做全稿润色。

**Q2：报告里的分数是检测器分数吗？**
不是。分数是对写作模式（套话密度、句长均匀度、模板结构）的本地启发式统计，不代表任何外部服务的测量结果，更不说明文字由谁写。详见 SKILL.md「诚实边界」。

**Q3：支持什么文件格式？**
纯文本（.txt）、Markdown（.md）、**Word（.docx）**、以及 **PDF（v1.6.0 起实验性
直读，限英文文本型；加密/扫描件拒收，CJK/嵌入字体尽力识别并拒收、可能漏网——
抽取结果请人工检查）**。stdin 也支持：
`echo "文本" | python scripts/detect.py`。

**Q4：会改坏我的数据吗？**
机械清理层设计上不触碰数字/引用；深改层由 agent 按指南执行，改完必须过 `verify.py`——数字、统计量、DOI、PMID、年份、缩写、术语表任何丢失都会 exit 1。守卫还会对「凭空新增的数字」告警（编造防线）。历史实测：改写中 p 值篡改、两臂互换、整句含电话号码误删，全部被守卫拦截过。

## 使用

**Q5：一定要跑四个脚本吗？**
不用。`python scripts/pipeline.py draft.txt -o out.txt` 一条命令跑完自查→清理→守卫→报告。多脚本入口是为需要单独调用某一步的场景保留的。

**Q6：术语表（--terms）怎么准备？**
先跑 `python scripts/extract_terms.py 原稿 -o terms.txt` 自动生成草稿（大写缩写、
书名号/引号内术语按频次排序），人工删改后使用。每行一个术语，`#` 开头是注释。
医学文本建议补充：药名（含商品名）、基因符号（鼠源首字母大写形态如 Myc 也要列）、
量表名、仪器名。不提供术语表时，守卫仍查数字/DOI/PMID/年份/全大写缩写。

**Q7：退出码怎么看？**
`verify.py` 是严格契约方：`0`=完整性 PASS、`1`=完整性 FAIL（有数字/引用/术语被动过——修改改稿，不是改守卫）、`2`=用法或文件错误。`detect/transform/compare/pipeline` 把判定写在输出报告里，完成即返回 `0`（用法/文件错误 `2`）——按退出码分支的脚本请以 verify.py 为准。所有脚本支持 `--version`。

**Q8：检测误报了正当术语怎么办？**
两层解决：①词表自带术语保护（mutational landscape、pivotal trial、robust regression、序列对齐、沉淀反应、心室重塑、串联质谱等已豁免）；②仍误报的，在 `scripts/patterns_*.json` 的 `term_guards` 加一条你的搭配（allow_before/allow_after），并欢迎反馈补充词表。

**Q9：分数多少算"有问题"？**
0-27 低（正常）；28-49 中（有模板腔，可改可不改）；50+ 高（建议按指南深改）；报告会给出具体剩余特征清单。分数是密度统计，短文本（<15 单元）自动降权并标注"仅供参考"。

## 迁移（自旧版页面）

**Q10：我是从旧版页面过来的，有变化吗？**
功能全集在这里且只增不减：旧版全部能力（双语自查/机械清理/深改手册/完整性守卫/前后对比）+ v1.1.0 新增（一键管线 pipeline.py、FAQ、完整示例、错误码体系）。旧页与本页同源同版本维护。

**Q11：旧页和新页内容一致吗？版本号什么关系？**
内容完全一致，同一份代码库双页发布，版本号两页保持同号（如两页同时是 v1.2.0）；仅某一页需要追修时该页用 x.x.1 子版本号。过渡期例外：旧页因迁移历史存在 +0.0.1 偏移（如本页 v1.1.0 对应旧页 v1.1.1）。以后更新认准 **paper-rewriter**（本页）；旧页永久保留作为入口。

**Q12：旧版评分 3 分是怎么回事？**
那是平台对「迁移说明占位页」的评分（页面只有搬家通知，没有功能），不代表工具本身——本页 v1.0.0 实测均分 4.55（trust 维 5.0）。

## 边界

**Q13：能保证某种评审结果吗？**
不能，也不承诺。本工具改善写作质量与自然度；任何承诺「保证不被判为机器生成」的服务都不可信。合规义务（AI 使用披露）在作者本人，见 references/compliance.md。

**Q14：多大文本算"太大"？**
v1.4.0 起不再需要手动切分：detect/pipeline 对超 1MB 文本**自动分块**处理（按段落
边界，报告会标注分块口径与块数），内存峰值恒定。注意完整性守卫（verify.py）始终
整文比对——这是红线语义，不可分块。

**Q14c：--structure 的章节降权会不会帮作者"藏住"方法段的机器味？**
不会。降权只归一综合分（方法段的固定句式是领域惯例，公平计量）；各章节原始分
仍在报告中逐项展示，任何人都能看到完整数据。「藏匿」不是本工具的设计，也
不符合它的诚信立场（见 compliance.md 拒绝清单）。

**Q14b：报告能导出成网页吗？能一次扫整个目录吗？**
都能。`--html report.html` 生成单文件 HTML（无外链可直接存档/转发）；compare 的
HTML 含逐句增删对照，复核改稿最直观。批量：`--batch 目录名` 一次扫全部
.txt/.md/.docx（detect 出逐文件评分，pipeline 逐文件清理+守卫汇总 CSV）。

**Q14a：transform 的激进模式（-a）什么时候用？**
适合：非正式文本的破折号堆叠、空泛开场白清理。不适合：学术方法段的插入语破折号、
任何将直接提交的文本（改完必须人工复核）。普通模式（不带 -a）已经能清模型残留、
客套句、标点与安全填充语——先跑普通模式看报告再决定要不要 -a。

**Q15：博客/公众号/公文这类非学术文本，评分偏高怎么办？**
用 `--profile general`：学术八股和公文过渡语在人写的非学术文本里是常态，general
模式把这些信号降权 60%（黑话、模型残留、节奏信号不受影响）。默认 `academic`
始终按学术论文口径标定，处理论文时不需要加参数。

**Q16：这个工具会联网吗？会读我的其他文件吗？**
不会、不会。全部脚本仅 Python 标准库、零网络请求；只读取你作为参数传入的文件，
只写入你用 `-o`/`--suggestions`/`--html`/`--track` 指定的输出路径；不读环境变量、不创建子进程和定时任务。
详见 SKILL.md「权限与环境声明」。

**Q17：2026 年了，检测技术都在进步，这套"质量优先"路线还成立吗？**
更成立了。公开研究显示：①单纯同义转写并不能让文字变好——质量优先路线的
价值不随工具演进贬值；②节奏与结构层面的建议之所以有效，是因为它们让文字
回归真实写作的质量，本工具不以任何外部产品为目标或参照；③正式学术文体被
自动化评审误判仍是行业痛点——被误判的真实作者依然是第一等用户。质量优先
是写作本身的标准，长期成立。
